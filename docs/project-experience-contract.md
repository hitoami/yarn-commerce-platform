# 作品体验与内容编辑合同

日期：2026-09-06。任务来源：[Issue #22](https://github.com/hitoami/yarn-commerce-platform/issues/22)。

本文件承接 PRODUCT.md 中已确认的产品决定，规定各页面职责与内容来源；不是本地任务追踪器，也不是当前 Shopify 后台已经完成接线的操作指南。实施状态、验收证据与后续任务以 Issue / PR 为准。

2026-09-06 补充确认：当前原型覆盖 YarnPal 的「发现作品 → 作品详情 → 制作准备 → 教程」核心路径，并加入材料与成品购买、定制咨询及队友通过 Shopify 自主编辑的闭环；不复制整个 App 的非核心功能。完整实施范围与技术验收统一收敛到 Issue #23；实际字段与后台路径见[编织作品内容模型](project-content-model.md)。

定制边界已确认：作品页提供「咨询定制」，顾客提交颜色、尺寸等需求，由团队人工确认可制作性、报价和交期；不做自动报价、在线配置器或商户后台。咨询不产生订单、不收费，也不承诺能够制作或按某日交付。接收位置与通知方式尚未完成验证，发送开关保持关闭；内部验收不得向真实顾客或商户擅自发送测试咨询。

## 一、已确认的核心体验

- 2026-09-08 用户确认简化为「逛」与「搜」。本节更新旧版独立商品搜索、作品/商品切换及复杂筛选建议；目标尚未实现，不改变商业首发范围。
- 首页以作品推荐和分类预览为中心，保留「有成品 / 可买材料 / 仅灵感」就地筛选。分类图标继续页内定位；各分类「查看全部」进入统一结果页，携带分类与已选购买方式，继续浏览对应作品。
- 首页搜索框与导航放大镜共用搜索页；提交非空关键词即搜索全站作品与商品，不继承原分类、购买方式或其他浏览筛选。结果页显示本次关键词，让用户清楚当前在搜什么。
- 搜索结果同页直接展示「相关作品」与「相关商品」两组，不要求用户切换类型，也不分别保存两套筛选。没有命中的组隐藏；两组都无命中时明确反馈并允许修改搜索词，不将推荐内容计为命中。
- 关联作品与同款成品同时命中时在各自分组保留；作品卡标明实际购买能力并进入作品详情，商品卡显示商品类型与价格并进入商品详情。仅灵感作品正常参与搜索，不虚构购买或教程入口。
- 首版匹配作品与商品自身名称、说明及明确维护的用途；命中作品不自动扩展为关联材料或工具命中。商品自身用途符合查询仍可直接命中，关联材料继续在作品详情展示。字段、查询、排序和分页的实现映射另行验证。
- 旧版难度、时间、教程类型等高级筛选不作为本轮简化搜索的必需界面；具体构图另行设计。
- 2026-09-09 用户确认手机搜索沿用首页的手绘分类图标，以「包袋、围巾、家居、玩偶」为基础增加「全部」，按实际内容扩展。分类在当前关键词结果中按作品类别与商品明确维护的用途筛选，保留同页两组结果。
- 搜索是独立页面，首页导航不显示选中态。手机视觉以用户选择的稿 3 为基础继续修订，不视为最终实施验收。
- 作品详情说明做什么、难度与准备条件、材料方案和教程；按实际内容显示模块，不要求每件作品都有所有模块。
- 作品不以本店供给齐套为展示门槛。材料清单与销售范围分开，允许部分材料本店提供、部分自备或资料待补；工具清楚说明是否包含，按需购买，不自动加购。
- 材料购买在「制作准备」中；底部「开始制作」定位到本页教程区，不要求先购买。图文分步骤展开，支持嵌入的视频页内播放。
- 希望直接拥有作品的用户可从作品详情进入关联成品 Product 的购买流程；没有对应成品时不伪造可售入口。定制咨询与购买分开，不产生订单。
- 2026-09-09 用户明确作品与商品的爱心收藏须在登录后跨设备保存，并有统一的收藏入口。这更新此前不纳入收藏的决定；本轮确认需求与视觉方向，身份接入、服务实现与验证另行细化。公开浏览和教程仍无账号门槛，不新增学习中心、付费墙或制作进度系统。「开始制作」不是建立 Making 的隐式指令。
- 评分系统暂不设计。卡片简介说明用途，难度、时间、规格和价格只展示实际适用且有内容依据的信息，不虚构评价或数量。
- YarnPal 是用户指定的 Project UX 参考，不代表批准复制其素材、付费机制或全站视觉风格。

## 二、页面保留、合并与补充

下表中首页、作品发现、作品详情及买材料分工已经确认；帮助与政策的合并方式是基于本次审计的实施建议，不改变实际政策内容。

| 页面或入口 | 处理 | 唯一职责与边界 |
| --- | --- | --- |
| 首页 | 保留并调整作品组织 | 品牌开场沿用已批准视觉；新手精选负责推荐起点，找灵感负责更广泛探索。两者不各建一套内容库 |
| 找灵感与作品发现 | 保留作品中心的浏览方式 | 首页就地筛选购买方式，分类图标页内定位；「查看全部」携带分类及购买方式继续浏览作品。提交关键词时转全站搜索，不继承浏览条件 |
| Project 作品详情 | 补充 | 作品信息、制作准备、材料购买入口与本页教程。不能再把作品卡片直接跳第一件商品视为已经完成作品详情 |
| 统一搜索页 | 同页分组查找作品与商品 | 首页搜索框与导航放大镜共用；非空关键词搜索全站，同页展示相关作品、相关商品，无类型切换与双套筛选，无命中组隐藏；作品与商品分别进入各自详情，不复制内容或库存 |
| Product 商品详情 | 保留 | 所买物品的图片、规格、包含内容、价格、可售配置与购买。毛线商品不冒充作品；套件仍是 Product |
| 教程区 | 合入作品详情 | 图文与视频按实际来源展示。基础技巧可按需查看，不为当前主路径另造学习中心 |
| 帮助 / Contact | 建议合并重复咨询入口 | 共用咨询说明与联系表单；说明用户应提供什么信息，不虚构响应时限 |
| 配送、退换、隐私等政策 | 保留独立事实页与入口 | 商品页使用链接或共用的简要说明，不能按模板区块序号维护不同版本政策 |
| 导航「新品」等历史入口 | 建议移除误导名称或修正其目标 | 当前全部商品 A–Z 不是新品排序；没有运营依据时不新增假新品栏目。上线前核对旧 URL 与菜单兼容，不删商品 |
| 无完整教程的 Inspiration | 保留既有内容，不混充 Project | 「找灵感」只是前台栏目名，不意味着把既有 Inspiration 数据直接转换为可执行作品 |
| Cart / Checkout | 保留 Shopify 流程 | 不自建支付、订单或库存真值；作品入口不得复制商业事实 |

## 三、Shopify 内容的唯一编辑来源

Project 的实际字段键、类型和后台路径以[编织作品内容模型](project-content-model.md)为准；下表继续规定内容职责，不要求运营人员从目标描述猜测录入位置。

| 内容 | 唯一维护入口 | 复用位置 | 预览检查 |
| --- | --- | --- | --- |
| 作品名称、简介、封面 | 内容 → `yarn_project` Metaobject | 首页卡片、作品结果、作品详情 | 改一次名称，检查三处一致；商品标题不随之被覆盖 |
| 难度、预计制作时间、类别、适用对象、节日 | 同一 Project 记录 | 作品筛选、摘要与详情 | 选择该条件能找到作品；空值不推定为简单、快速或适合所有对象 |
| 学习目标 | 同一 Project 记录 | 有相应内容的作品详情 | 无内容时隐藏，不生成虚假教学承诺 |
| 主要教程图文、视频来源 | 同一 `yarn_project` 的教程富文本与来源 URL | 教程类型筛选、作品教程区 | 类型来自实际可用内容；开始制作能定位到该区；无法嵌入的来源不伪造播放能力 |
| 可复用基础技巧 | 首期随同一 Project 的教程内容维护 | 关联作品的基础技巧区 | 首期不新建 Tutorial 实体；未发生实际复用前不扩展独立管理体系 |
| 通用线材要求、物理用量、配色要求、工具规格 | Project 的 Material Requirements | 制作准备、适用的作品筛选 | 工具规格与要求一致；通用重量或长度不能被商品团数替代 |
| 推荐商品、Variant 与采购数量 | Project 的 Product Recommendations / 既有套件引用 | 推荐材料和购买入口 | 引用真实商品配置；团数与所选规格匹配，不复制价格库存 |
| 作品关联成品 | `yarn_project.finished_products` 的 Product 引用 | 作品详情的成品购买入口 | 引用 Shopify 商品，不把作品封面视为可售商品；不同设计只能标为参考，无引用时不造购买按钮 |
| 定制咨询说明与开关 | `yarn_project.customization_enabled` 与 Theme 发送开关 | 作品详情与咨询入口 | 携带作品身份与用户需求；提交不产生订单、收费或承诺，接收方式以实际验证为准 |
| 工具是否包含、补齐工具推荐 | 以既有可售配置真实组成与作品要求为依据 | 制作准备和方案明细 | 已包含的工具不重复推荐，未包含的必要工具明确说明；用户选择后才加购 |
| 商品标题、说明、图片、Variant、价格与库存 | Shopify Products | 买材料列表、商品详情、推荐商品、Cart | 修改后各处读取 Shopify，移除代码按 handle 或区块位置覆盖的例外 |
| 材质、单团重量 / 长度等商品事实 | Product 的适用结构化字段 | 商品筛选、商品详情、材料匹配 | 只填写可核实值；作品用量与单团规格分别维护 |
| 精选作品选择、顺序、栏目标题、显示开关 | 主题编辑器的对应 Section / Block | 首页 | 选择引用而非粘贴作品内容；无有效内容时有真实空状态或隐藏，不补造卡片 |
| 商品分类标题、说明、商品归属、排序 | Shopify Collections 及对应主题显示配置 | 商品分类视图 | 名称与结果和排序一致，不以硬编码标签 URL 假装后台菜单生效 |
| 导航名称与链接 | Shopify 菜单 | 桌面导航、移动导航、适用页脚 | 两种导航读取相同来源，语言与链接目标一致 |
| 联系说明、普通帮助正文 | Shopify Pages；重复入口只引用 | 帮助页、Contact、首页帮助入口 | 联系页正文可编辑；复用入口不维护另一份冲突事实 |
| 退换、配送、隐私等政策正文 | Shopify 对应 Policies；无对应类型的帮助使用 Pages | 政策页和全站引用 | 保留政策真值；商品页短说明不产生独立规则 |

### 编辑可靠性约束

- Project 卡片、筛选与详情不保存三份相同内容。作品与 Product 是不同事实，也不能为省一次录入而混为一个实体。
- 页面缺失数据时隐藏可选内容或明确缺口，不用代码填充假教程、假评价、用量或政策。
- Project 使用 `yarn_project` Metaobject 与 `/pages/projects/{handle}` 路径；现有 Inspiration 编辑入口不能当作新作品管理入口。具体录入方式见[内部原型操作指南](project-prototype-operator-guide.md)。
- 后台定义、访问权限、主题配置和内容条目不随 Theme Git diff 自动完成部署；实施时必须分别核验。
- 作品搜索不能只筛选一个截断的前端数据子集，却宣称搜索了全部作品。数据量、分页、查询、语言与浏览器返回行为在实现前验证。
- 普通材料单独补购、整套加购方式、库存变化及部分失败处理尚需在实施设计中明确；本合同不暗示 Shopify 已有任意组合的一键套件功能。

## 四、翻译与预览合同

- 简体中文为内容主版本；日文是消费者默认发布语言，英文与中文可切换。翻译对应同一作品 / 商品记录，不新建三套目录。
- 内容翻译在 Shopify 对应资源的翻译入口维护；主题通用控件使用 locale。字段键、稳定选项值与精确商品规格不随语言改变。
- 新元对象及其字段的翻译支持、实际语言发布状态必须现场核验。前台语言路径为日文 `/`、简体中文 `/zh` 与英文 `/en`；后台以中文为 primary 不能用来推断根路径语言异常。英文已按用户本次授权发布，PR #16 的历史发布缺口不再作为当前阻塞；每轮仍须单独验证受影响路径，不能因语言已开放就勾选通过。
- 预览固定选择未发布主题；日文 `/` 与简体中文 `/zh` 已核对，英文 `/en` 仅在发布获授权后验证。后台入口与路径规则见内容模型，不以 Metaobject 为 Active 推定其他前台结果通过。
- 每类内容用一条代表性修改验证「后台保存 → 引用页面显示 → 已发布语言核对」；英文获授权发布后再补 `/en`。涉及临时改动运营数据时先获得当次授权，验证后按授权范围恢复。
- 视觉验证至少覆盖 1440 px Desktop 与 390 px Mobile，截图打开复核；长标题、空内容、选项展开、清除、无结果、返回和购物车路径均需检查。

材料与成品的桌面购买路径已分别用真实 Variant 验证到加入购物车、数量增加 1 和进入 Shop Pay 结账入口，未下单或支付；验证后只移除本次加入的条目，保留原有购物车。这是购买路径的有限验证，不证明材料适配、成品同款、商品编辑、移动端购买或真实交易已经验收。

## 五、教程与演示内容边界

用户当前没有完整作品教程。需要验证实际流程时，由助手协助寻找少量合适来源；不因此阻塞当前结构规划，也不将占位内容当作真实验收。

待选教程应能支持完整作品，而非仅展示一个针法；核对材料要求、可售商品适配、语言可用性及来源使用方式。记录原作者与来源，分别确认链接、嵌入和转载方式；公开可看不等于允许复制。

内容不完整的待制作作品不公开承诺能够跟做完成，内部演示与公开发行分开。2026-09-06 后续确认：本店未供应全部配件不等于作品内容不完整，也不阻止销售其中真实可售的配件；部分销售明确包含与缺项，不冒充完整材料包。真正承诺完整跟做时，才需要核实完整教程与制作要求。

2026-09-06 用户确认本轮采用 2–3 个可替换样例，以页面、购买入口和后台编辑可操作为验收目标，暂不要求真实销售或跟做交付标准。教程应有可合法链接或嵌入的来源；未核实的材料用量、供货等明确标注。受保护的内部演示可以展示这些未完成样例，但不得因此将 Draft Project 公开发布，或将参考商品与演示报价当作真实供货承诺。具体预览隔离方式实施前验证，不能仅以 URL 含 preview 参数证明受保护。

演示样例须能由队友通过 Shopify 替换，不能写死在 Theme 中。验证实际购买操作时仍须读取 Shopify 的真实 Product / Variant 状态并明确其演示用途；缺少对应商品时显示缺口，不伪造可购买状态。正式教程、材料适配、样品试做与供货验收单独保留，不阻塞本轮内部原型的技术验收，也不因技术验收通过而被标为完成。

## 六、实施顺序与边界

1. 先核对现有 #15 / PR #16 的可复用内容接线与未完成语言验收，避免重复修改；不擅自合并或丢弃其工作。
2. 先用一条代表性样例验证内容定义、后台编辑、翻译、同页教程与材料引用，再补足 2–3 个可替换内部演示样例。视觉执行采用 AGENTS.md 中用户批准的本轮例外，不再逐页请求构图选择；内部技术闭环可按第五节验收，但没有完整教程时不能关闭真实跟做交付验收。
3. 在 Project 可编辑、可展示之后，接入首页新手精选和找灵感列表、搜索与筛选；使用同一份内容，不迁移非指导型 Inspiration 冒充作品。
4. 按本合同统一买材料、商品详情、菜单和帮助的内容来源；移除审计发现的代码覆盖，逐项验证真实后台编辑结果。
5. 每次只实施一个 Issue。后续任务、依赖、状态与验收只记 GitHub；不在本文件维护并行进度。

不新建 Platform Service，不迁移 Headless，不更改既有实际价格库存或政策，不删除既有内容，不发布 production，不提交真实订单。凡涉及页面视觉变更，仍须按本轮例外继承批准方向，并执行检测、三语双端截图与 finish review；本轮文档不是视觉完工证明。

最终交接须包含真实可用的受保护预览与后台入口、队友新增作品并关联教程 / 商品的操作说明、验证证据及已知缺口。代理须亲自验证代表性的新增 / 修改 / 首页选择闭环；队友亲手试用及 Slack 反馈属于后续人工验收，不将代理代测记成队友已通过，也不未经授权自动发送 Slack 消息。
