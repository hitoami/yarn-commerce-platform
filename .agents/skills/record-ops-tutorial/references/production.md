# 录制、配音与剪辑

开始制作时读取。这里描述已验证的方法和限制；工具可用性、窗口 ID、文件位置和字体必须在当前环境核对，不照抄上一次的临时路径。

## 录屏准备

- 通过 `load_workspace_dependencies` 获取当前可用 Python/Node 路径，检查 FFmpeg、ffprobe、中文字体、Pillow 和所选语音合成工具。按需使用已有依赖，不先安装一整套工具。
- 用户要求真实屏幕录制时，可用系统录制程序采集窗口；网页操作仍走浏览器工具。新开的 Chrome 标签可能在后台，自动化能读取页面不等于录制窗口能看到它。
- 必要时请用户把目标 Chrome 窗口放到前台；这是录制条件，不是重复请求已批准的店铺操作。固定窗口尺寸，录制期间避免移动、缩放或切换到无关标签。
- macOS 已跑通 `screencapture` 窗口定时录制。先查看本机帮助并动态找出目标 Chrome 窗口；不要硬编码窗口 ID。以下只在参数已核对后使用：

```sh
/usr/sbin/screencapture -v -V "$capture_seconds" -C -k -l"$capture_window_id" "$raw_video"
```

`capture_seconds` 是有限时长；按操作量留余量，必要时分段。该方法曾在发送 SIGINT 后丢失输出文件，应等定时录制正常结束再剪掉尾部等待。不能把「录制进程启动成功」当作已得到素材；检查退出状态、文件存在和可解码内容。录制中持续给用户状态更新，单次阻塞等待保持在 60 秒以内。

## 操作与时间基准

- 时间记录保留动作名称和时间戳；录屏起点以文件元数据及可见动作校准。工具调用返回时间可能晚于画面变化，不能当作精确帧边界。
- 录制前验证输入方式：富文本、iframe、数字输入框对 End、全选和追加输入的行为可能不同。保存前读取完整字段或当前数字，防止把 `1` 后追加 `0` 变成 `10`。
- 实测可靠的策略是精确定位文本末尾后输入；不支持时用工具文档允许的填值方式，再读回值。逐字输入仅在有助于教学可见性时使用。
- 主题编辑器可能在后退后停在空白页。重新从当前页面的「查看模板」进入并核对同一模板与语言，不能凭旧位置继续点。
- 出错后只做少量针对性重试；只要外部状态不确定，就先读回。不要为了录到漂亮动作反复创建订单或发送通知。

## 剪辑计划

每段记录：原素材、起止时间、裁切范围、动作标题、讲解文字、语音起点、输出时长。裁切范围统一约定为 `x, y, width, height`；调用 FFmpeg 时转换为 `crop=width:height:x:y`，避免顺序混淆。

建议成片基准为 1920×1080、30 fps、H.264/AAC、像素比例 1:1、显示比例 16:9。用户已确认的样片或明确要求优先。

- 原生录屏可能是高分辨率、60 fps，且黑边会随窗口位置改变。先抽帧定位内容区域；窗口若移动，按稳定区间分别裁切，不能套一组坐标到整条视频。
- 用内容区等比缩放和留边，禁止硬拉伸。进入路径保留导航，输入时可适度放大字段。裁切后确认保存条没有被切掉。
- 可预留上方章节条、下方字幕条；不要把浏览器标签和书签当作课程内容。具体颜色与高度沿用获批样片，无需写成网站全局设计规则。
- 输入、点击、保存结果使用连续视频帧。静态卡片只解释没有实际录制的概念或待办，并明确其性质。
- 剪短等待时保留动作因果。剪辑说明可写「已剪短加载等待，对重点操作区域放大，部分片段放慢配合讲解」。

## 配音与字幕时间

已用过的中文配音起点是 `zh-CN-XiaoxiaoNeural`、语速 `-5%`；确认当前工具支持即可，不把特定服务作为唯一依赖。网络语音合成只提交整理后的讲解文案，不提交录屏、客户资料或原始后台文本。

1. 每个动作段单独生成声音，同时保存文本和词边界。缓存键至少包含文字、声音、语速；修改任何一项就重新生成。
2. 以 ffprobe 读取真实音频时长，不能从文本长度推算。词边界若以 100 ns 为单位，除以 `10,000,000` 转秒；核对服务的实际单位。
3. 按中文标点和画面宽度分句，用词边界将字幕对应到音频。没有边界时改用可用对齐方法或人工抽听，不能宣称已精确同步。
4. 设源片段长度为 `R`、配音长度为 `A`、语音延迟为 `d`、尾部留白为 `p`，输出段长可取 `D = max(R, d + A + p)`，向上对齐到输出帧。明显拖慢操作时先改短讲解。
5. 片段字幕时间加上 `d`，合并时再加之前各段的**实际输出时长**。音频末尾补静音到 `D`，避免下一段画面出现时上一句仍未结束。

FFmpeg 如果没有 libass / subtitles 滤镜，可以用 Pillow 渲染透明字幕 PNG，再按字幕时段覆盖在真实视频上；这只是文字覆盖层，不能替换实操素材。渲染前测量字体宽度，保留短字幕和必要换行；不裁掉溢出的文字。

## 拼接和质量检查

- 每段统一编码参数、分辨率、帧率和音频采样率。用输入侧 `-ss` 定位长素材可减少重复解码；最终仍需检查剪切边界是否准确。
- 独立 AAC 片段直接拼接可能出现时间戳或累计偏移。已跑通的方法是视频参数一致时复制视频，重新编码合并音频，使用 `aresample=async=1:first_pts=0`；最终核对整段声音，不仅看命令成功。
- 输出设置 `+faststart` 便于在线播放。在合成阶段明确像素比例；若 H.264 码流比例与容器不一致，修正后核对 ffprobe 的 SAR/DAR，避免播放器拉伸。
- 缓存必须包含原素材标识、起止点、裁切、讲解、语音起点和渲染参数。修正字幕或声音后不能因为旧文件存在就跳过重建。

最少验证：

```sh
ffprobe -v error -show_streams -show_format -of json "$final_video"
ffmpeg -v error -xerror -i "$final_video" -f null -
```

另核对所有字幕满足 `0 ≤ start < end ≤ 成片时长`，相邻字幕无意外重叠；音视频时长接近（本流程以差值不超过约 0.2 秒作为排查起点）。抽听开头、关键输入/保存处、各拼接处和结尾；检查音量可听且无削波，不能只用「有音轨」判定声音合格。

抽帧覆盖每个业务动作与恢复结果。先用联系表定位问题，再看原尺寸关键帧和实际播放；全片解码不证明文案正确、字段可读或字幕同步。

Slack 附件卡片可能暂时显示 `0:00`；先确认上传已处理完成，再打开播放器核对真实时长和能否播放。不能因缩略卡时长为零重复发送同一条消息。
